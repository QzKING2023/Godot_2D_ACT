# 美术资源工作流

本工作流的三个月限时执行版本见 [`PIXEL_ART_PRODUCTION_PIPELINE.md`](PIXEL_ART_PRODUCTION_PIPELINE.md)。该文件保留本页规则，并补充资产预算、提示词模板、审核门槛和备选方案。

## 项目视觉基线

- 游戏画面的逻辑构图为 320×180。
- 像素美术使用 16×16 网格处理小细节，使用 32×32 网格处理角色、敌人和大型道具。
- 美术源文件与项目运行路径分开保存。源参考图和可编辑文件放在运行时导出目录之外，只有审核通过的运行时资产才导入 Godot。

## 导入规则

- 像素美术使用 Nearest 过滤。
- 需要保持像素清晰度的精灵和 UI 使用 Lossless 压缩。
- 避免运行时缩放产生平滑效果，尽量使用整数倍缩放。
- 扩大资产批次前，先验证一个角色、一个环境瓦片、一个效果和一个 UI 资产。

## 生产顺序

1. 先用程序化占位图形验证移动、战斗时序、碰撞、HUD 布局和摄像机取景。
2. 场景构图稳定后，再用 CC0 环境和道具参考替换占位图形。
3. 使用 GPT Image 进行概念探索、背景探索、氛围参考和构图研究。
4. 在 Pixelorama、LibreSprite 或 Aseprite 中手工清理选定的关键帧和精灵。
5. 清理后的帧和锚点审核通过后，再制作 Sprite Sheet。
6. 在 Godot 中制作粒子和 UI 效果，使它们保持可调节和数据驱动。

生成图像属于概念或源素材。未经审核的生成图像不得直接作为最终 Sprite Sheet。

## 许可与来源记录

每个外部或生成资产都要记录以下信息：

- 资产名称和用途。
- 来源 URL 或本地源路径。
- 许可证和署名要求。
- 获取日期以及修改内容。
- 对于生成素材，记录提示词、模型、生成日期、参考图路径和选中的版本。
- 是否批准进入运行时导出。

将这些记录放在项目文档旁边，确保后续替换资产时不会丢失来源信息。
