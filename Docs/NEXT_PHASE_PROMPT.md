## 下一阶段目标

先对最小核心循环做独立验收和稳定化，再进入一个可展示的单关卡纵向切片。不要同时推进大量新机制。

## 第一阶段：读取和审计

1. 读取项目根目录及相关目录中的 `AGENTS.md`。
2. 检查 `project.godot`、输入映射、现有 C# 脚本、场景、资源目录和 Git 状态。
3. 确认当前最小核心已经实现的内容，不要假设提示词中的功能都已完成。
4. 建立当前功能清单和阻塞清单。
5. 不覆盖用户已有修改，不删除现有脚本、场景或资源。

## 第二阶段：最小核心验收

必须逐项验证：

- 角色可以移动。
- 角色可以跳跃。
- 角色可以普通攻击。
- 角色可以闪避。
- 角色可以格挡。
- 角色可以使用 K 位移技能。
- 时缓可以启动。
- 时缓会持续消耗资源。
- 资源耗尽后时缓停止。
- 敌人可以发起可识别攻击。
- 角色受击、格挡、闪避和无敌状态产生不同结果。
- 完美闪避和完美格挡窗口使用 `0.25` 秒时间参数，不固定换算成帧数。
- K 位移方向随方向输入变化。
- Xbox Controller 输入映射可以被读取。
- 键盘输入和控制器输入不会互相覆盖。
- 测试场景可以重置。
- 不产生未注册的输入、事件或卡牌行为。
- 调试日志能够记录关键状态切换和错误。

如果验收失败，优先修复阻塞最小核心运行的问题。修复时保持职责分离，不要继续把所有逻辑堆到单一脚本中。

## 第三阶段：建立最小纵向切片

只有第一阶段和第二阶段稳定后，才推进以下内容：

1. 创建一个很小的可通关测试关卡。
2. 放置少量平台、障碍，并用边界条件触发场景切换。
3. 添加一至两个简单 AI 敌人，若时间不足则保留一个 Boss。
4. 设计一个具有明确攻击节奏和可读前摇的 Boss。
5. Boss 至少有以下行为：
   - 普通攻击。
   - 可格挡或可闪避攻击。
   - 一种需要使用时缓或位移技能处理的攻击。
   - 受击反馈。
   - 清晰的死亡和重置流程。
6. 关卡可以从开始进入战斗，并以 Boss 击败作为结束条件。
7. 使用占位图形或程序化绘制，不等待最终像素美术。
8. 不新增复杂装备、技能树、背包、剧情、掉落或长流程。

## 第四阶段：输入和手感约束

保持以下映射：

- WASD / 左摇杆：移动方向。
- Space / Xbox A：跳跃。
- 鼠标左键或 J / Xbox X：攻击。
- Left Shift / Xbox B：闪避。
- Left Ctrl / Xbox RB：格挡。
- Q / Xbox LB：时缓。
- K / Xbox Y：位移技能。
- E：交互。
- R：重置测试回合。

如果 Xbox B 与交互存在冲突，必须记录最小改动方案。目前交互使用键盘 E，B 保留给闪避。

需要验证：

- 输入缓冲。
- 闪避和格挡无敌。
- `0.25` 秒完美窗口。
- 时缓资源消耗。
- K 位移碰撞。
- Boss 前摇与反馈。
- 受击、硬直、死亡和重置。

## 第五阶段：测试与验收

建立轻量、可重复的测试方式：

- 场景启动测试。
- 输入映射测试。
- 角色状态切换测试。
- 时缓资源测试。
- 受击、格挡、闪避测试。
- Boss 攻击测试。
- Boss 死亡和关卡重置测试。
- 最小可玩流程测试。

不得运行无界循环，不得生成大量临时构建产物。验证日志只保留必要信息，以及种子、版本、配置、起止时间和退出状态等最小元数据。
