# 2D ACT Demo 执行计划

跨平台执行提示词见 [`PHASE_PROMPTS.md`](PHASE_PROMPTS.md)。每次只复制固定前缀和一个阶段提示词。

## 已锁定目标

在十二周内交付一个 Windows 版本的 10–15 分钟可玩纵向切片：

- 一段包含少量平台、障碍和一个交互点的短流程。
- 一个 Boss 场地和一个 Boss。
- 一个使用现有核心循环的玩家角色，包括移动、跳跃、攻击、闪避、格挡、时缓、K 位移技能和重置。
- 一个包含三种可读攻击节奏的 Boss：
  1. 可以格挡或闪避的普通攻击。
  2. 必须使用闪避或 K 位移处理的破防或抓取攻击。
  3. 鼓励移动或使用时缓处理的延迟范围攻击。
- 清晰的前摇、生效、恢复、受击、死亡、胜利和重置反馈。
- 已验证的键盘和 Xbox Controller 输入映射。
- 可重复构建的版本和简短 QA 记录。

Demo 范围不包含第二关、装备、背包、技能树、长剧情、掉落系统或大型敌人图鉴。

## 当前起点

仓库已经包含一个可运行的占位战斗房间，入口是 `Scenes/CoreLoop.tscn`，主要组装逻辑位于 `Scripts/ACT/Arena/TestArena.cs`。当前代码已经拆分出玩家、敌人、战斗解析、时缓管理器、HUD、输入适配器和可选的 headless smoke test。`project.godot` 已配置移动、跳跃、攻击、闪避、格挡、时缓、K 位移技能、交互和重置的键盘与 Xbox 输入。

旧的 `main.tscn` 和 `SpikeMain.cs` 是早期原型入口。当前基线使用 `Scenes/CoreLoop.tscn`。旧原型在没有单独清理任务前保留。

当前构建命令通过，0 个警告，0 个错误：

```powershell
dotnet build "ACT Spike.csproj" --no-restore
```

当前开发 Shell 中 Godot 可执行文件不在 PATH。进入打包阶段前，记录 Godot 4.5.1 Mono 的实际路径，并在缺失时手动安装匹配的导出模板。

## 完成定义

满足以下条件后，Demo 才算完成：

1. 全新启动可以进入可玩关卡，不依赖编辑器内的临时设置。
2. 玩家可以完成前段路线并进入 Boss 场地。
3. 每种 Boss 攻击都有独立的视觉或音频前摇，并且在 320×180 逻辑构图下清晰可读。
4. 三种攻击对应不同的正确处理，包括格挡或闪避、K 位移或闪避、移动或时缓。
5. 玩家可以获胜、失败，并且无需重启编辑器就能重置遭遇战。
6. 时缓按住时启动并消耗资源，资源耗尽时停止，并按现有配置恢复。
7. `0.25` 秒完美闪避和完美格挡仍使用时间戳计算，并且可以独立配置。
8. 键盘和 Xbox 输入都能工作，互不覆盖。
9. Windows 导出可以根据仓库和已记录的引擎、模板版本重新构建。
10. 所有运行时美术都经过手工制作或清理，并在资产清单中明确批准。生成图像不直接作为 Sprite Sheet 发布。

## 每周执行计划

按每周 15–20 小时估算，其中约 10–12 小时用于实现，3–5 小时用于美术或视觉清理，2–3 小时用于试玩和记录。每周五结束前完成一次干净构建和一次完整试玩。如果某个门槛未通过，下周先修复该门槛，再增加内容。

### 第 1 周：基线和验收工具

交付内容：

- 确认当前入口场景、引擎版本、输入映射和现有 smoke test。
- 编写玩家、敌人、时缓、重置和控制器路径的手工验收清单。
- 把含义不清的占位文本改成明确的状态和事件反馈。
- 验证参考构图和适合整数倍缩放的摄像机比例。
- 用一个短练习学习美术编辑器，描摹并导出一个 16×16 图标。这个练习不计入生产资产。

退出条件：全新工作目录可以构建并启动当前场景，现有核心循环 smoke test 通过，或存在一个已经命名且可复现的失败。

### 第 2 周：灰盒关卡路线

交付内容：

- 用碰撞安全的占位形状搭建起点、短流程、交互点和 Boss 场地。
- 完成摄像机边界、出生点和重置点。
- 加入 Boss 被击败后的临时胜利条件。

退出条件：玩家可以从起点走到场地，并连续三次回到干净的重置状态。

### 第 3 周：Boss 契约和第一种攻击

交付内容：

- 完成 Boss 生命周期，包括出生、待机、前摇、攻击、恢复、受击硬直、死亡和胜利。
- 完成带有明确前摇、可格挡或可闪避的普通攻击。
- 完成 Boss 生命值、玩家死亡和场地重置。

退出条件：玩家可以使用现有普通攻击击败 Boss，失败后无需重新加载编辑器即可重试。

### 第 4 周：其余攻击和时序

交付内容：

- 完成需要闪避或 K 位移处理的破防或抓取攻击。
- 完成可以通过移动或时缓处理的延迟范围攻击。
- 为前摇、生效、恢复、受击硬直和重置建立明确的时间配置。
- 在当前循环确实需要的位置补上输入缓冲和无敌检查。

退出条件：每种攻击都有一个预期处理方式，并且命中、格挡、闪避、完美闪避和完美格挡都会产生可区分的结果。

### 第 5 周：路线和交互

交付内容：

- 完成灰盒平台布局、障碍位置和一个交互点。
- 调整摄像机取景，让玩家、前摇和 Boss 同时清晰可见。
- 加入简单的开始提示和进入 Boss 场地提示。

退出条件：完整灰盒流程需要 5–10 分钟，没有死路，并且任何失败状态都可以重置。

### 第 6 周：核心循环稳定化

交付内容：

- 补齐时缓消耗与恢复、Boss 死亡、重置和控制器映射的 smoke 覆盖。
- 修复状态泄漏、输入冲突、碰撞边界问题和错误反馈。
- 连续完成三次灰盒胜利和三次受控失败。

退出条件：核心循环没有已知阻塞项，后续工作可以转入视觉和呈现。

### 第 7 周：美术风格试制

每种类别只制作一个审核样例：

- 玩家攻击或闪避帧。
- Boss 前摇或攻击帧。
- 一个环境瓦片或道具。
- 一个受击或前摇效果。
- 一个 HUD 元素。

按 `Docs/PIXEL_ART_PRODUCTION_PIPELINE.md` 执行。先锁定调色板、描边方式、光照方向和接地线规则，再制作更多帧。

退出条件：五个样例在原生构图下属于同一套视觉语言，并且缩小到 320×180 后仍然可读。

### 第 8 周：替换高价值占位资源

交付内容：

- 玩家待机、攻击、闪避、受击和死亡或胜利关键帧。
- Boss 待机、前摇、三种攻击关键帧、受击和死亡关键帧。
- 路线需要的环境瓦片集。
- 保留程序化效果处理时序关键反馈。

退出条件：完整 Boss 战斗在没有调试文字的情况下仍能被理解。

### 第 9 周：呈现处理

交付内容：

- 背景层、少量可复用道具、HUD 清理以及胜利和失败表现。
- 每类攻击最多加入两条短音频占位，不让最终配乐阻塞交付。
- 从默认视图中移除只用于调试的文字，同时保留可选调试模式。

退出条件：Demo 录屏无需开发者旁白，就能说明路线、Boss 状态和胜利条件。

### 第 10 周：可读性和控制器

交付内容：

- 调整前摇对比度、受击停顿或闪白、摄像机取景和资源条可读性。
- 验证键盘、Xbox Controller 和 Hitbox 友好的键盘输入。
- 如果保留 B 键用于闪避而交互继续使用键盘 E，在 QA 记录中写明选择。

退出条件：第一次接触的玩家经过一次说明后，能识别三种 Boss 应对方式，并在没有调试覆盖层的情况下完成战斗。

### 第 11 周：试玩和回归

交付内容：

- 完成三次结构化试玩，或三次独立的自测，并记录问题。
- 只修复影响通关、可读性、输入或重置的前五个问题。
- 运行干净构建、smoke test、手工验收清单和全新目录启动检查。

退出条件：没有 P0 或 P1 问题阻塞完整流程，剩余问题均为已记录的美术或表现问题。

### 第 12 周：候选发布版本

交付内容：

- Windows 导出，并记录 Godot、编辑器和模板版本。
- 写一份包含控制方式、已知限制和重置方法的简短 README。
- 完成资产来源清单和最终 QA 记录。
- 完成一次最终的 10–15 分钟录屏或现场演示。

退出条件：没有打开编辑器的人也能启动、游玩、获胜或失败、重置，并理解结果。

## 范围控制

不能削减玩家核心循环、一个 Boss、攻击可读性、胜利或失败或重置、输入验证和可重复构建。

进度落后时按以下顺序削减：

1. 装饰道具和背景层。
2. 路线长度和可选交互内容。
3. 多余动画帧，保留关键姿势并延长静止帧。
4. 一类攻击超过一条的音频。
5. 第二个普通敌人或训练遭遇战。
6. 第三种 Boss 攻击只有在前两种攻击无法在最终门槛前做清楚时才削减。削减时要记录范围变更。

进度压力下不新增系统、不更换引擎版本、不替换战斗架构，也不在第 7 周风格试制通过前批量生成美术资源。

## 可重复检查

构建命令：

```powershell
dotnet build "ACT Spike.csproj" --no-restore
```

Headless smoke test。先找到 Godot 4.5.1 Mono 可执行文件：

```powershell
$env:ACT_SMOKE = "1"
& "<Godot-4.5.1-mono.exe 的路径>" --headless --path . --log-file ".godot\\headless-smoke.log" --quit-after 900
Remove-Item Env:ACT_SMOKE
```

在受限运行环境中，显式指定 `--log-file`，避免 Godot 无法创建默认的 `user://logs` 目录。`--quit-after` 计的是主循环迭代数而非秒数：设得太小（如 10）会让 smoke 在只完成第一阶段（攻击命中）时提前退出并返回假阳性 0；smoke 跑完全部阶段后会自行 `Quit(0/1)`，900 帧是让它自然结束的安全上限。

手工验收必须覆盖：

- 移动、跳跃、普通攻击、K 位移技能、闪避、格挡和时缓。
- 时缓资源消耗、耗尽停止和恢复。
- 三种 Boss 攻击的前摇、生效和恢复。
- 使用时间戳计算的 `0.25` 秒完美闪避和完美格挡。
- 命中、格挡、闪避、受击硬直、死亡、胜利和重置。
- 键盘和 Xbox 映射，且不存在跨设备覆盖。
- 全新启动和 Windows 导出。

只记录命令、引擎或模板版本、配置或种子（如果使用）、起止时间、通过或失败状态以及最小必要的失败说明。
