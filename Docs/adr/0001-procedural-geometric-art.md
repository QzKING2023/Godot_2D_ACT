# 采用纯 2D 程序化几何美术替代生成式与像素管线

Status: accepted

ACT Spike 放弃此前基于开源绘画模型、GPT Image 与手工像素清理的美术管线，全面改用 Godot 原生 2D 程序化几何表现（零外部静态贴图或 3D 模型资产），并以原生 `1280×720`（`canvas_items` 缩放）取代原有的 `320×180` 像素网格约束。开源绘画模型在动作可读性与风格一致性上持续达不到预期，且后续手工修图与帧清理阻塞了单人项目的交付速度。

## 考虑的选项

- **开源绘画模型 + GPT Image + 像素手工清理**：概念探索成本高，动作帧一致性难以控制，单人交付周期不可控。
- **外部 2D 矢量/部件导出 + 骨骼拼装**：仍需维护外部作图工具与资产导入管线，不如纯代码几何迭代直接。
- **3D 低模几何体正交渲染到 2D**：需引入 3D 场景/光照/SubViewport 复杂度，偏离现有 `CharacterBody2D` 2D 代码基线。

## 后果

- 所有运行时视觉（角色、Boss、攻击前摇、环境、受击与时缓反馈、HUD）均由 2D 几何原语、Shader 与粒子在引擎内直接驱动。
- 仓库内遗留的 ComfyUI 工作流、AI 概念图提示词与像素生产管线文档已作废，需从工作树清理以免误导后续开发。
- 美术设计聚焦于轮廓剪影、配色层级、动态形变与战斗前摇可读性，而非精细二次元线稿或像素逐帧绘制。
